### 3. Agent Communication and Implementation

Agents do not operate in isolation; they communicate via the Orchestrator through structured protocols to ensure data integrity and workflow sequencing:

1.  **Communication Protocol:** Agents communicate via structured **JSON** objects, defining input, output, and triggering conditions.
2.  **Workflow Sequencing:** The Master Orchestrator manages the flow, such as sequentially routing information from the **Story Analysis Agent** to the **Visual Language Agent**, and then in parallel to the **Budget Expert Agent** and **Shot List Generator Agent**.
3.  **Voice-First Integration:** Voice notes are transcribed by the **Voice Transcription Agent**, which then classifies the content (e.g., creative note, technical requirement, to-do list item) and routes the specific actions to the relevant agents (e.g., routing a director's shot idea to the **Shot List Generator**).

#### Implementation Strategy

The project utilizes a highly parallelized development strategy using multiple **Claude Code instances** simultaneously to achieve the desired rapid timeline (weeks of work compressed into days or hours).

*   **Instance Allocation:** Separate Claude Code instances are assigned different components, such as Core Infrastructure, Input Agents, Analysis Agents, Technical Agents, and Output/Management Agents.
*   **Infrastructure Build:** Requires setting up the Firebase project, initializing the GitHub repository, configuring necessary APIs (Claude, OpenAI), and deploying the RunPod GPU environment.
*   **Code Base:** The system uses Python 3.11+ and FastAPI for API endpoints, with agents built using the Claude SDK and organized into a modular file structure (e.g., `/agents/orchestrator`, `/storage/firebase.py`).

### 1. The Multimodal Vision Agent (Eagle-Eye) and RunPod Integration

The **Multimodal Vision Agent** (also known as the **Eagle-Eye Agent** or **Location Analysis Agent**) is critical for translating complex visual data—such as location photos and reference images—into actionable technical and creative notes.

#### Technology and Deployment

This agent requires significant computational power, making it reliant on specialized infrastructure:

*   **Infrastructure:** The Multimodal Vision Agent runs on **RunPod GPU Instances**. These GPU instances, potentially using high-end cards like the A100 or RTX 4090, are necessary to run large, open-source multimodal models efficiently.
*   **Model Selection (Qwen and Alternatives):** The system specifically prioritizes newer open-source multimodal models that are evaluated as being **better than Gemini 2.5 Pro** at visual analysis. Key candidates for deployment include:
    *   **Qwen2-VL-72B / Qwen3-VL-235B:** These models are selected for their **excellent visual reasoning** and strong spatial understanding capabilities.
    *   **Molmo:** This model is targeted specifically for its **pointing capability**. This unique feature allows the agent to visually indicate specific areas in images, such as **rigging points** or **motivated light sources**, providing highly specific feedback to the G&E teams.
    *   **InternVL 2.0/3.0** and **LLaVA-NeXT** are also noted as strong alternatives for spatial understanding and detailed image analysis.

#### Core Functions and Use Cases

The agent processes visual input (often **location-tagged photos**) and turns it into structured data for other agents:

1.  **Location Analysis:** Analyzes location photos to assess lighting conditions (quality, direction, time of day), space dimensions, angles, and composition. It can generate **lighting diagrams** and identify **practical lighting opportunities**.
2.  **Reference Breakdown:** It can analyze reference images to identify and describe the technical setup, such as estimating focal length, depth of field, and the overall composition breakdown.
3.  **Coordination:** It flags obstacles, power availability, rigging points (using pointing capability), and potential Art Department needs based on the location's visual characteristics.
